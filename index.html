PFO 2: Sistema de Gestión de Tareas con API y Base de Datos

Materia: Programación sobre Redes

1. Endpoints de la API Flask

  • POST /registro: Recibe {"usuario": "...", "contraseña": "..."}, genera el hash seguro y persiste el usuario en SQLite.
  • POST /login: Compara las credenciales ingresadas contra el hash en la base de datos para habilitar el acceso.
  • GET /tareas: Retorna la vista HTML de confirmación de servidor operativo.

2. Respuestas Conceptuales

¿Por qué hashear contraseñas?

Para evitar guardar texto plano en la base de datos. Un hash criptográfico es unidireccional (irreversible). Si la base de datos se filtra, los atacantes no obtienen las contraseñas reales. Además, el uso de salt asegura que dos contraseñas idénticas generen hashes distintos, anulando ataques con tablas precalculadas (Rainbow Tables).

Ventajas de usar SQLite en este proyecto

  • Serverless (sin servidor): No requiere instalar ni configurar motores externos como MySQL o PostgreSQL.
  • Portabilidad: Todo el esquema y registros residen en el archivo local tareas.db, facilitando respaldos y clonación del repositorio.
  • Librería estándar: Python incluye el módulo sqlite3 de fábrica sin dependencias extras.

3. Guía de Ejecución Local

  1. Instalar paquetes: pip install Flask requests
  2. Iniciar el backend: python servidor.py
  3. En otra terminal, correr el cliente: python cliente.py
